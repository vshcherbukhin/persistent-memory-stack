## Executive summary

Release 4.0.34 removes repeated graph-fact payloads from `recall_context`, bounds
the response size, avoids model work for semantically unchanged updates, and
separates graph content versioning from ordinary memory metadata changes.

The same isolated corpus and workload were run against the released 4.0.33
baseline and the 4.0.34 candidate. Across 24 recall queries, total estimated
tokens fell **74.0%** and duplicate-fact bytes fell **100%**. All 24 expected
memories were still retrieved, all six agent-answer samples still passed, and no
cross-project result or dangling fact reference was observed.

| Total estimated tokens, 24 queries | 464,168 | 120,802 | **-74.0%** |

| Maximum response bytes | 50,715 | 12,959 | **-74.4%** |
| Median estimated tokens | 19,340 | 5,033 | **-74.0%** |
| p95 estimated tokens | 19,353 | 5,043 | **-73.9%** |
| Maximum estimated tokens | 19,361 | 5,043 | **-74.0%** |

| Agent input tokens, 6 samples | 131,081 | 33,284 | **-74.6%** |

The 4.0.34 p95 result is below the **16 KiB soft target**, and its 12,959-byte
maximum is below the **24 KiB hard cap**. The token counts use the benchmark's
configured tokenizer; byte limits remain the deterministic enforcement boundary.

| --- | ---: | ---: | --- |
| Expected-memory hits | 24/24 | 24/24 | Pass |
| Expected-memory hit rate | 100% | 100% | Pass |
| Mean reciprocal rank | 0.8323 | 0.8115 | Pass: -0.0208 |

| Cross-project leaks | 0 | 0 | Pass |
| Dangling fact references | 0 | 0 | Pass |

The five validated planes are memories, graph facts, entity expansions,
timeline entries, and contradictions. The MRR gate requires at least 0.80 and
allows no more than a 0.03 decline from baseline. The candidate's 0.8115 score
and -0.0208 delta both pass. This reports the observed rank movement instead of
hiding it, while the expected-hit and agent-answer checks confirm that the
evidence required to answer stayed visible.

## Update token routing

| Update operation | 4.0.33 model tokens | 4.0.34 model tokens | 4.0.34 behavior |
| --- | ---: | ---: | --- |
| Exact no-op | 12,793 | 0 | Returns without extraction, embedding, or Graphiti |
| Session-only | 0 | 0 | Persists the local field only |
| Same project | 7,927 | 0 | Returns without project-move work |
| Identical metadata | 12,942 | 0 | Returns without model work |
| Metadata-only change | 11,541 | 4,896 | Retains fact validation; skips embedding and Graphiti |
| Real content change | 15,330 | 16,366 | Retains extraction, embedding, and Graphiti work |

The real-content row is a preservation check, not a reduction target: a changed
memory must still refresh its semantic vector and temporal graph. Small run-to-run
model-token variation is expected. The optimization target is work that cannot
change semantic search or graph facts.

## What changed

- `recall_context` returns a canonical `facts` registry. Graph, entity, timeline,
  and contradiction views reference those facts instead of repeating full objects.
- Response packing uses deterministic priority and budgets, with previews,
  omission counts, and follow-up memory/entity/node identifiers when the complete
  result does not fit.
- Update routing distinguishes exact no-op, local/session-only, same-project,
  identical-metadata, metadata-only, content, and project-move changes.
- A durable `graphVersion` advances only when graph content changes. Recall/access
  metadata no longer produces new Graphiti episodes.
- Project moves reconcile the authoritative Postgres row, Qdrant payload, and
  Graphiti provenance under the same project boundary.

## Method and release gates

Both candidates used corpus `p0-token-quality-v1` in separately named disposable
benchmark stacks. The suite issued 24 recall queries, evaluated six grounded
agent answers, measured update-operation usage by service, and verified cleanup
of its containers, volumes, networks, and images.

The comparison fails if expected-memory recall or the six agent answers regress;
if any project leak or dangling reference appears; if MRR falls below 0.80 or by
more than 0.03; if p95 exceeds 16 KiB or maximum exceeds 24 KiB; or if the token,
byte, duplicate-payload, and agent-input reductions miss their minimum thresholds.
It also fails if no-op updates invoke a model, metadata-only updates invoke
embedding or Graphiti, or real content changes stop doing required semantic and
graph work.

## Interpretation and limits

This result demonstrates a large reduction for the fixed release corpus and
workload. It does not claim that every production query will have the same
percentage reduction, that retrieval rank is identical, or that model-generated
facts are universally correct. The benchmark protects the behaviors most likely
to be harmed by compaction: complete expected recall, grounded answer quality,
graph-plane visibility, temporal/contradiction data, scope isolation, and usable
follow-up references.
